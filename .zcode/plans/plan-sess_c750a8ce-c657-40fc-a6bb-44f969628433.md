## Terms & Privacy pages

Create two linked pages—**`/terms`** and **`/privacy`**—consistent with Montara’s existing website. No new dependencies or deployment.

### Design
- Reuse the public header/footer and existing `Section` heading component.
- Keep Montara’s navy/amber colors, Outfit headings, and Work Sans body text.
- Use a restrained, content-first layout: readable article width, numbered sections, generous spacing, and a compact “On this page” navigation with anchor links.
- Include links between the two policies and a contact link using `site.email`.
- Ensure mobile stacking, visible keyboard focus, and anchor offsets that clear the fixed header.

### Content
Write initial English policy copy tailored to this software-services website, rather than an account-based product.
- **Terms of Use:** website scope, acceptable use, intellectual property, third-party links, website information/disclaimers, separate written agreements for client projects, policy changes, and contact.
- **Privacy Policy:** information voluntarily shared by email, technical information involved in hosting and analytics, purposes of processing, service providers, security and retention considerations, privacy requests, external links, policy changes, and contact.
- Acknowledge the analytics script already included in `app/layout.tsx`; do not claim the site has no tracking.
- Do not invent a registered legal entity, jurisdiction, retention duration, cookie behavior, or compliance guarantees. Identify the copy as an initial draft requiring owner/legal review before publication; do not imply an approved effective date.

### Implementation
1. Add thin route files in `app/(public)/terms/page.tsx` and `app/(public)/privacy/page.tsx`, following the existing route convention.
2. Add policy content components under `components/block/site/`, with a small shared legal-page presentation component for consistent article and contents-navigation markup.
3. Set page-specific titles, descriptions, canonical URLs, and matching social metadata using the existing metadata constants.
4. Add **Terms of Use** and **Privacy Policy** to the Company footer links in `data/site.ts`; keep primary navigation unchanged.
5. Run the requested design-guidance lookup during implementation; preserve the established site design rather than introducing a new visual system.

### Verification
- Run lint, formatting checks, and TypeScript checking; format only changed files if needed.
- Run the Vinext build directly to avoid the existing `prebuild` script’s repository-wide formatting/autofixes.
- Check both routes in the browser at desktop and mobile widths, including footer links, cross-policy links, section anchors, keyboard navigation, heading hierarchy, and overflow.
- Report any validation blockers and the remaining legal-review requirement. Leave all changes local and uncommitted.
